# GitHub OAuth on Expo web

## Changes

- Added a session controller and React provider: restores saved app JWTs via
  `/api/v1/me`, saves exchanged JWTs before verifying `/me`, and clears state and
  storage on logout or 401. Network/server errors preserve the token and offer
  retry. Generation checks and serialized storage writes prevent late requests
  from reversing logout. Storage failures produce visible recovery messages.
- Added a web-only Home authentication panel showing loading, errors, account
  name/email, retry, sign-in, and logout. Native panel remains empty; Android
  authentication is not implemented by this chunk.
- Added Expo AuthSession GitHub login with code response, generated state,
  S256 PKCE, and `user:email`. Popup starts from the button click; successful
  validated responses send the original verifier and identical callback URL to
  the existing API. Each prepared request can exchange once; retries remount the
  request to generate fresh PKCE/state. Cancellation is quiet; popup/provider/API
  errors are shown. Provider secrets remain on the backend.
- Added `/auth` outside the tabs. Its client effect calls
  `WebBrowser.maybeCompleteAuthSession()`; direct visits offer a Home link.
  Moved Home/Explore under `(tabs)` with unchanged public URLs. Root keeps the
  existing theme/splash and supplies a Stack and session provider.
- Fixed the existing router-slot/Pressable ref type mismatch. Explicitly enabled
  React, React Native, Node, and Jest ambient types for TypeScript 6.
- Added SDK-map versions of expo-auth-session (~58.0.17) and expo-crypto
  (~58.0.7) through `expo install`. Expo lint also declared eslint and the
  SDK-compatible eslint-config-expo; added its standard flat configuration.
  **Installation failed due to npm registry DNS restrictions (EAI_AGAIN). These
  declarations still need installation and lockfile regeneration locally.**
- No backend contracts, schemas, Android login, or existing documentation changed.

## Finish locally

From `client/`:

```sh
rtk proxy npx expo install expo-auth-session expo-crypto
rtk proxy npm install
rtk npm test -- --runInBand
rtk npm run test:coverage -- --runInBand
rtk proxy npx tsc --noEmit
rtk proxy npx expo lint
rtk proxy npx expo-doctor
rtk proxy npx expo start --web --port 8081
```

Commit the regenerated package-lock.json with package.json. Keep any existing
dependency advisories tracked separately; do not run audit fix --force.

With the existing API running and its normal database configured:

1. Confirm client API URL is `http://localhost:8080/api/v1`; GitHub public web
   client ID is present in the ignored client env. Keep the client secret and
   JWT signing key only in the API env.
2. Open `http://localhost:8081` (use localhost, not a LAN IP). The callback
   generated by AuthSession must be `http://localhost:8081/auth`, registered
   exactly with GitHub and the API allowlist. API CORS must allow the web origin.
3. Click GitHub sign-in; confirm the authorization URL contains code_challenge,
   code_challenge_method=S256, state, and user:email. Complete real login.
4. Confirm popup closure, POST `/api/v1/auth/github`, then GET `/api/v1/me` 200
   with the app Bearer token. Never copy tokens into documentation or screenshots.
5. Reload the original tab: `/me` restores the profile from sessionStorage.
6. Log out: storage and profile clear. A request to `/me` without a token must
   return 401. Sign in again and confirm the same database account is reused.
7. Close/cancel the popup and try again. Stop the API while restoring a session:
   confirm a readable error, retained token, and a successful retry after restart.
8. Replace the saved token with an invalid/expired test value and reload: confirm
   401 clears it. Visit `/auth` directly: return-home fallback must work.

Real provider login, browser popup behavior with the installed SDK, and database
reuse are **pending manual verification**, not claimed as passing here. Logout
is local: it does not revoke GitHub authorization or invalidate an already issued
app JWT. No refresh token flow is added; an expired session requires sign-in.
