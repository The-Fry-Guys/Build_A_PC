# Visitor onboarding

Use this checklist for both directions of the class exchange; the repository
[README](../README.md) and [runbook](runbook.md) are the visitor's instructions.

## Before the exercise

- Confirm the repository is public and ready, and create the GitHub issue label `onboarding`.
- Record team numbers, assign visitors and hosts, and set the class timebox.
- Hosts answer questions verbally and do not take control of the visitor's keyboard.

## Visitor run

- Follow the host repository's README and runbook toward a running stack and test run.
- Record every command and its result, including failures, in the submission log.
- File one `onboarding` issue per blocker with the exact README step, command, actual output, expected result, OS version, and Docker version.
- If the run is clean, file one `onboarding` issue listing the commands and results instead of blocker details.

## Triage and submission

- Before class ends, assign an owner to every onboarding issue or record its response plan.
- Submit both team numbers, who visited and hosted, links to issues filed in each direction, visitor command logs, and each student's visitor/host half.
